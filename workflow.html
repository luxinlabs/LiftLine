The solution

An automated service line that knows
where to look, and when to stop

Deterministic

Safety comes first

The call starts with a fixed safety question that no model can override. Danger words later in the call also go straight to a human dispatcher.

Typed AI

Jev picks the data source

TypeSafe Jev chooses the system for each workflow question. Every choice carries a confidence score and passes through an allowlist. Anything uncertain stops.

Closed loop

Dispatch and notify

The case, work order, and notifications are written atomically. With the caller's consent, Photon iMessage sends the report and ETA.

LiftLine is a structured workflow, not an open-ended chatbot. The AI decides where to look; business rules decide what happens.

End-to-end workflow

From ring to technician in eight steps

Twilio
1

Call received

The webhook fires and the Twilio request signature is verified before anything runs.

Rule
2

Safety triage

Trapped, injured, or unsure? Press 1 or 3 for an immediate dispatcher handoff.

Twilio
3

Identify

Machine number by speech or keypad, read back to confirm. Registered phone number plus a hashed PIN.

Jev
4

Route

Jev maps each workflow question to a data source. Confidence must be at least 0.80 and the source must be on the allowlist.

SAP · IoT
5

Investigate

Site-scoped equipment lookup, a telemetry freshness check (24 h or less), critical-code scan, and fault correlation.

SAP
6

Coverage

Warranty and contract check. Billable visits require explicit caller approval.

CRM · Field
7

Dispatch

Duplicate-case check, certified and available technician, then one atomic write for the case, work order, and outbox.

Photon
8

Notify & confirm

Consent-gated iMessage report. The dispatcher accepts and the ETA becomes final.

HandoffIf any check fails, the call goes to a human dispatcher. That covers unverified callers, stale telemetry, low Jev confidence, duplicate cases, and no available technician.

Sponsor · TypeSafe Jev

Typed AI decisions with calibrated confidence

Routing brainlift_agent/router.py
How we call it
# POST https://api.typesafe.ai/v1/systemone { "model": "jev-latest", "state": { "workflow": "Elevator fault intake…", "catalog": SOURCES }, "questions": { "equipment": { "type": "choice", "instructions": "Resolve a machine number…", "criteria": SOURCES }, …7 questions } }

Privacy by design. Jev only receives the schema catalog and the workflow questions. PINs, phone numbers, and caller transcripts are never sent.

Guardrails on every answer
  • The choice must equal the allowlisted source for that question
  • Confidence must fall between 0.80 and 1.00 and be finite
  • The probabilities must cover the full catalog and sum to 1 ± 0.01
  • The chosen source must have the highest probability
  • Every decision is logged with the model version and confidence
Fail-closedAny violation, timeout, or bad payload raises RoutingUnavailable and hands the call to a dispatcher.

Sponsor · Twilio

The phone line and the conversation engine

Voice intakelift_agent/voice.py · server.py

Speech + keypad capture

Twilio <Gather> takes speech with a DTMF fallback. Machine numbers are read back digit by digit to confirm.

TwiML state machine

Each webhook advances a persisted call state: safety → machine → PIN → describe → approval → consent. The webhooks are retry-safe.

Human handoff

Safety flags and failed checks transfer the caller to DISPATCHER_PHONE. If the transfer fails, the caller hears emergency guidance.

Webhook security
# Every request must carry a valid signature X-Twilio-Signature = base64( HMAC-SHA1(TWILIO_AUTH_TOKEN, url + sorted(params))) # tampered URL or param → rejected # tests/test_workflow.py covers both
Plus · ElevenLabs

An optional natural voice (eleven_flash_v2_5) replaces <Say> with cached MP3 audio. If synthesis is unavailable, it falls back to Twilio speech.

LIFTLINE
Trust

Safety and security built into every layer

Safety
  • Deterministic triage runs before Jev or any data lookup
  • Danger words at any later step interrupt the call and trigger a handoff
  • A critical telemetry code in the last 30 minutes also triggers a handoff
  • LiftLine never says an elevator is safe to use
  • The ETA stays provisional until the dispatcher accepts
Security
  • PINs hashed with PBKDF2-SHA256, a per-contact salt, and 200k iterations
  • Registered phone number and PIN required. Lockout after 5 failures per hour
  • Twilio signatures verified. Admin APIs require a bearer token
  • Parameterized, site-scoped SQL throughout
  • Redacted logs. Live mode refuses synthetic data
